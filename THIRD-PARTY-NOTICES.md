The repository is private and the software is **not currently distributed**, so that
licence is a statement of intent rather than an active grant to anyone — but the

Last reviewed: 2026-09-18.

**This file is the reasoning; [`licenses/`](licenses/README.md) is the evidence.** The
resolved transitive tree for every image — `pip-licenses` run *inside* the containers,
`license-checker` over the web app's production tree, and `syft` SBOMs that catch the OS

`tests/test_licensing_guards.py` enforces. Dated runs, with deltas, live in
[`docs/audits/`](docs/audits/README.md). The tables below stay hand-written because
whether a licence is *acceptable* is a judgement; what is *installed* is not, and had
never been enumerated.

## 0. Commercial-use audit

Every dependency, against three questions:

1. **Does the licence permit commercial use?**
2. **Does it permit use in a deployed service** — not merely experimentation?
3. **Does it restrict commercial use of the generated output?**

Question 2 is the one that catches things a licence tag does not: `openai/clip-vit-*`
is tagged MIT and its model card puts *all* deployed use out of scope. Question 3 is
the revenue gate — a restriction there would mean the mesh could be generated legally
and the printed part could not be sold, which is the whole business.

**Question 3 only bites for generative models.** A library has no claim on what a
program built with it produces, and neither does GPL or AGPL: the standard reading, and
the FSF's own, is that a program's *output* is not a derivative work of the program.
The G-code CuraEngine emits is this project's, and the fact that CuraEngine is AGPL does
not change that. So Q3 is answered "no restriction" for everything except the model
weights, where it is answered from each model card.

Verification level is marked per row: **[v]** read from the licence text or model card
during this audit; **[d]** taken from the package's own declared metadata or its SPDX
identifier.

### Findings and actions

**1. The CUDA worker image cannot be redistributed freely.** Running
`nvidia/cuda:12.4.1-devel-ubuntu22.04` on your own GPU host is unambiguously fine. But
NVIDIA's redistribution route for the CUDA driver libraries is narrow: the result must
be a Docker container distributed *on Docker Hub or NGC*. Pushing the built
`trellis2-worker` image to a private registry — ECR, GCR, GitHub Container Registry —
is not obviously covered. **Action:** if the worker image is ever distributed rather
than built where it runs, get that reviewed. Building it on the GPU host from this
repo avoids the question entirely.

**2. `opencv-python` shipped Qt 5 under LGPLv3, and nothing here uses OpenCV.
Resolved.** All `opencv-python` wheels bundle FFmpeg (LGPLv2.1) and the **non-headless**
Linux wheels additionally bundle Qt 5 (LGPLv3). `requirements-base.txt` pinned *both*
builds while `import cv2` appears nowhere in this project's own code — it is a
transitive requirement of the upstream sculptor stack. The non-headless pin is removed,
with a comment recording why, so that "why is only the headless one here" is not
answered by adding the other one back.

> Scope correction, recorded because it was overstated when this finding was first
> written: **the images never carried this.** `base.Dockerfile` only *copies*
> `requirements.txt` and never runs `pip install -r` against it, so image contents come
> from explicit pip lines — and `trellis2-worker.Dockerfile` already installed
> `opencv-python-headless` by name. The LGPLv3 payload reached only a **native**
> install, which is the macOS development path.

**3. `gmpy2` was LGPL-3.0-or-later. Resolved.** Optional acceleration for `sympy`, which
is itself transitive via torch. Nothing imports it and `sympy` works without it, so the
pin is removed rather than the obligations documented.

**4. The runtime requirements contained a publishing toolchain. Resolved.** `twine`,
`keyring`, `readme_renderer`, `docutils`, `nh3`, `id`, `jaraco.*` and `backports.*` were
pinned in `requirements-base.txt` — pip-freeze leakage from a publishing environment.
Licence-clean, pure surface area, removed as a cluster since each existed only to serve
`twine`.

**5. Nothing in the dependency set restricts commercial use of the output.** Every
generative model on the live path — FLUX.2-klein, TRELLIS.2, BiRefNet, SigLIP — permits
commercial use of what it produces, and the AGPL tools make no claim on the G-code. The
business model is not blocked by any current dependency. The two components that would
have blocked it, RMBG-2.0 and OpenAI CLIP, are both structurally excluded and guarded
by tests.

### Weak copyleft — file-level

**pywebpush** and **py-vapid** — **MPL-2.0**, added 2026-09-18 with web push
(issue #159). `server/push.py` imports them to send one notification per job reaching
`awaiting_verdict`: `py-vapid` signs the VAPID JWT that identifies this server to a
push service, and `pywebpush` encrypts the payload (RFC 8291) and posts it.

MPL-2.0 attaches its obligation to the licensed *files*, not to the program that uses
them (§ 1.10, § 3.3): a "Larger Work" may be distributed under any terms, and what must
stay available is the source of any MPL file that is modified. No file of either
package is copied, patched or vendored here — both are installed as their own wheels
and imported — so nothing in this repository is Covered Software, and the obligation is
met by shipping them unmodified with their licence text (it is in each wheel) and by
this notice. `http-ece`, which `pywebpush` uses for the content encoding, is MIT.

Why a dependency at all: the alternative was roughly 150 lines of RFC 8291 — ECDH
against the subscription's P-256 key, HKDF, AES-128-GCM and the `aes128gcm` header
block — on the `cryptography` already in the tree. It was refused because its failure
mode is a push service answering 400 on somebody's phone while every test in CI passes.
The decision is recorded in `licence_policy.REVIEWED_WEAK_COPYLEFT`.

`torchmcubes` (MPL-2.0) was removed with TripoSR — see
[§3 Removed components](#3-removed-components).

### Weak copyleft — library-level

**psycopg 3** (`psycopg`, `psycopg-binary`, `psycopg-pool`) — **LGPL-3.0-only**,
added 2026-09-05 when the telemetry database moved from a SQLite file to PostgreSQL on
Supabase. It is the driver `pythonsrc/telemetry/db.py` and `server/config_store.py`
import.

The LGPL's conditions on a "Combined Work" are met by construction: the library is
imported unmodified as a separate wheel (§ 4(d)(1) — a Python import is the dynamic
linking the licence contemplates, and a user replaces the library with `pip install`),
the licence text ships inside the wheel (§ 4(b)), and this file gives notice (§ 4(a)).
No source of psycopg is modified, so § 2 does not arise. `psycopg-binary` also carries
a bundled `libpq`, which is under the PostgreSQL Licence (permissive).

Why LGPL rather than a permissive driver: `pg8000` (BSD) is pure Python and would have
avoided the question, but psycopg 3 is the driver the PostgreSQL ecosystem — Supabase's
own Python guidance included — tests against, and its pool, its typed adapters and its
connection-loss semantics are what the telemetry layer's reliability rests on. The
decision is recorded in `licence_policy.REVIEWED_WEAK_COPYLEFT`, which is what turns
the scheduled audit's `flag` into an `allow` with this reason attached.

**The lettering font** (`pythonsrc/organizer/fonts/`). The decorative tier (F13, issue
#157) raises or recesses text on a face of an organizer, and the glyph outlines have to
come from a font file the repository controls. It is vendored rather than resolved at
runtime for the reason the whole parametric path exists: *the same spec must compile to
the same mesh, byte for byte*. A system font is not reproducible across two machines, a
downloaded one is not reproducible across two days, and a user-uploaded one would be a
third IP channel beside the prompt and the emboss box. So the file is committed, pinned
by sha256, and read by nothing but `pythonsrc/organizer/lettering.py`.

| Asset | Upstream | Version | Licence | sha256 |
|---|---|---|---|---|
| `DejaVuSans-Bold.ttf` | [DejaVu Fonts](https://dejavu-fonts.github.io/) | 2.35 | Bitstream Vera + public domain (DejaVu changes) + Bitstream Vera (Arev glyphs) | `b184b89e…aef167` |

`LICENSE` beside it is the upstream notice verbatim, carrying all three grants.
**The file is unmodified and unsubsetted**, which is a licence decision and not laziness:
the Bitstream Vera licence permits modification only under a renamed font, so a subset —
which is a Modified Version — could not keep the name this table attributes. The size
that costs (688 KiB) buys the guarantee that the bytes here are the bytes upstream ships.
Nothing in the grant reaches a *printed object*: the licence governs the Font Software,
and a chamfered slab of PLA with a name on it is not font software, so a part this
project makes carries no font obligation.

**Bold, and DejaVu rather than the app's own Barlow**, because both are printability
decisions before they are typographic ones. A raised glyph thinner than one extrusion
does not print, so the stem width at a given cap height is the constraint — DejaVu Sans
Bold's thinnest stroke is ~0,26 em, which keeps a 6 mm cap height at 1,5 mm of stem, half
again over `process.min_feature_mm`; a regular weight sits on the floor and a light one
under it. Barlow SemiBold (OFL-1.1, and what `web/src/global.css` brands the app with)
was the first choice and remains the better *typographic* one; it is not here because
fetching it needs the network and this repository's build must not, and switching to it
later is one file, one row and one sha256. **Not `matplotlib.textpath`**, which would read
the same outlines out of a plotting library's private data directory: the font would then
move with a matplotlib upgrade, and so would every lettered STL this project has shipped.

`tests/test_vendored_font.py` binds this row to the tree the way
`tests/test_vendored_skills.py` binds the skills table — the file, its `LICENSE`, the
sha256 here, and the sha256 the code pins — so a font swap cannot happen quietly.

shape path, so unlike the rasterizer (§ *nvdiffrast and nvdiffrec*) and the matte
weights (below) it **cannot be structurally avoided**; the model does not work
without it. That is acceptable, because the DINOv3 License **permits commercial
use**. What it requires:

- **Attribution.** "Built with DINOv3" displayed prominently. Carried in this
  file, in `README.md`, and in the application's UI footer
  (`web/src/App.tsx`).
- **Acceptable Use Policy.** No military, warfare, nuclear, espionage or
  weapons-development use, and no reverse-engineering of the underlying
  components.
- **Trade controls.** Use must comply with applicable export-control and
  sanctions regulations.
- **Propagation on redistribution.** Distributing the weights or a derivative of
  them is only permitted under the same agreement, with a copy provided. **Do not
  bake DINOv3 weights into a distributed image** — that converts a use into a
  redistribution and pulls the licence onto the artifact. The weights are fetched
  at run time into a named volume, which is why this stays a use.
- **Acknowledgement in publications** reporting research performed with it.

The repo is **gated**: access is granted per-account after accepting the terms, so
whoever accepted them with the project's `HF_TOKEN` is the licensee of record.

#### The checkpoint's background-removal weights are non-commercial and are overridden

> `microsoft/TRELLIS.2-4B`'s `pipeline.json` configures background removal as:
>
> ```json
> "rembg_model": { "name": "BiRefNet", "args": { "model_name": "briaai/RMBG-2.0" } }
> ```
>
> The **class** is BiRefNet (MIT). The **weights** are BRIA RMBG-2.0, published
> under **CC BY-NC 4.0** — free for non-commercial use only, with commercial use
> requiring a paid agreement with BRIA. Loading them would put a non-commercial
> restriction on the pipeline, exactly as `pymeshfix` did (§3).

This is the `rembg` / u2net hazard returning by a **different route**. The old one
was a library silently changing its default; this one is an upstream config file
naming the encumbered repo outright. The lesson generalises: **an explicitly named
model id is no protection when the id someone else named is the encumbered one.**
Read the id, not the class name.

Phase 2 therefore substitutes MIT BiRefNet weights
([`pythonsrc/sculptors/background.py`](pythonsrc/sculptors/background.py)):

- `permissive_rembg()` rebinds `trellis2.pipelines.rembg.BiRefNet` to
  `PermissiveBiRefNet` for the duration of `Pipeline.from_pretrained`. It must wrap
  the *load*, not follow it: upstream constructs the matte model eagerly, so
  reassigning `pipeline.rembg_model` afterwards would already have downloaded the
  BRIA weights and accepted their gated-repo terms to get there.
- `assert_permissive_matte()` then verifies the loaded pipeline actually holds the
  substitute. It checks the outcome rather than the mechanism, so the day upstream
  stops resolving that config entry through `getattr` the load **fails** instead of
  quietly reverting.
- `NON_COMMERCIAL_MATTE_MODEL_IDS` is a deny-list, enforced by
  [`tests/test_licensing_guards.py`](tests/test_licensing_guards.py).
- This covers the `trellis2` and `remote` backends both — the GPU worker imports
  this same code. It does **not** cover `pixazo`; see *Hosted services*.

> **Our MIT BiRefNet is still loaded with `trust_remote_code=True`**, matching
> upstream's own call. That executes modelling code fetched from the Hugging Face
> Hub at load time. MIT, so no licence hazard — but it is remote code execution on
> the GPU worker. Pin a revision via `$DS_BIREFNET_MODEL_ID` (`repo@sha`) before
> any untrusted deployment.

> **Do not reintroduce `rembg`** without restoring both of its old controls (a
> version pin *and* an explicitly named permissive model), and **do not remove the
> matte substitution** on the theory that upstream names its model explicitly. It
> does. That is the problem.

#### nvdiffrast and nvdiffrec must not be installed

> Upstream TRELLIS.2's documented install line includes `--nvdiffrast
> --nvdiffrec`. **Do not use it as-is.** Both packages are published under the
> **NVIDIA Source Code License**, which permits non-commercial research use only.
> Installing either into a Daedal Studio image would put a non-commercial
> restriction on a distributed artifact and make this project's Apache-2.0 grant
> incoherent — the same class of mistake as `pymeshfix` (§3).

This project avoids them structurally rather than by remembering not to type a
flag:

- **Phase 2 never rasterizes.** `Trellis2Backend` drives the pipeline stages
  itself and stops after shape decoding, so it never calls
  `o_voxel.postprocess.to_glb()`, which is the only thing on the image→3D path
  that needs a rasterizer. `trellis2/pipelines/__init__.py` resolves submodules
  lazily, so importing `Trellis2ImageTo3DPipeline` does not pull in the texturing
  pipeline or the renderers either.
- **The worker image does not install them.** Its `pip install` lines are
  explicit, and the renderer packages are absent.

An FDM printer consumes geometry, so nothing is lost. If a future feature needs
textured output — a preview render, a GLB export — the renderer must come from a
permissively licensed backend (PyTorch3D, BSD-3-Clause, is the substitution
upstream's structure accommodates), **not** from nvdiffrast. Adding one also
reopens the question for the CPU images, which currently need no rasterizer at all.

> **The upstream defaults this project overrides are not overridden on someone

> our copyright act, so this is a **contractual** exposure, not a copyright one:
> if a provider is not licensed for what it runs, the loss lands wherever the
> terms of service put it, and standard terms disclaim it. Before the `pixazo`
> backend is used for anything beyond the beta, get written confirmation from the
> provider that its deployment is licensed for commercial use and that generated

> Absent that, keep this backend beta-only. `create_sculptor()` already makes it
> swappable, so that costs nothing but a config change.

> **The blueprint leaves the machine when this backend is used.** `image_url` is
> either a `data:` URI or a public URL, so the prompt's rendered image is uploaded

## 3. Removed components

**pymeshlab** — removed 2026-08-27 by changing `trimesh[all]` to `trimesh[easy]`.

Never named by any manifest and never imported. `trimesh[all]` includes trimesh's own
`test-more` extra, so `infra/docker/pipeline.Dockerfile` and
`infra/docker/phase3.Dockerfile` had both been installing trimesh's **test**
dependencies into production images since Phase 3 was written: `pymeshlab` (GPL-3.0)
and `triangle` (LGPL-3.0). A GPL-3.0 extension module importable in the same
interpreter is the precise condition pymeshfix's removal ruled out, arriving by a
different route — a one-word requirement specifier with the licence two levels below it.

No obligation was triggered: the images were never distributed and nothing imported
either package. `trimesh[easy]` keeps the runtime extras and drops the test and viewer
sets.

**Found by the first run of the committed licence audit** — `licenses/report.json`
scored it `deny` on the day the workflow landed, which is the argument for committing
the resolved tree rather than auditing the manifests. `tests/test_licensing_guards.py`
now fails on any manifest naming `trimesh[all]`.

**pymeshfix** — removed 2026-08-20, replaced by `manifold3d` (Apache-2.0).

pymeshfix wraps MeshFix (M. Attene, IMATI-GE/CNR, 2010) and is published under
GPL-3.0 / AGPL-3.0 with an explicit additional condition: commercial use
requires a separately negotiated licensing contract with the authors and
IMATI-GE/CNR. It was previously imported in-process by `pythonsrc/engineer.py`,
which would have made the pipeline a derivative work of AGPL code and left
Daedal Studio's own Apache-2.0 grant incoherent.

**Do not reintroduce pymeshfix.** The replacement in `Engineer.repair_mesh`
composes trimesh (surface closing, MIT) with manifold3d (manifoldness guarantee
and boolean union, Apache-2.0).

**TripoSR** — removed 2026-08-20, replaced by TRELLIS.2-4B (MIT).

Removed for capability, not licence: TripoSR (MIT, © Tripo AI & Stability AI) was
compliant and is simply superseded. Its removal took three dependencies with it,
each of which had carried an obligation of its own:

| Gone with it | Was | Why it existed |
|---|---|---|
| `pythonsrc/tsr/` | MIT, vendored with local MPS patches | TripoSR's model source |
| `torchmcubes` | **MPL-2.0** (file-level copyleft) | Marching-cubes iso-surface extraction |
| `rembg` + `u2net` weights | MIT + Apache-2.0, both pinned defensively | Background cut-out before reconstruction |

The `torchmcubes` removal retires this project's only weak-copyleft dependency.
The `rembg` removal retires that package's version pin — but **not** the hazard it
was pinned against. TRELLIS.2 names its own background-removal model, and the model
it names *is* BRIA RMBG-2.0. The control moved rather than disappearing: see §2,
*The checkpoint's background-removal weights are non-commercial and are overridden*.

## Maintaining this file

When adding or bumping a dependency:

1. Check the licence of the package **and**, separately, of any model weights
   it downloads at runtime.
2. Reject AGPL/GPL for anything that would be imported in-process.
3. Reject "source-available, non-commercial" licences outright — the NVIDIA
   Source Code License is the live example. These are easy to miss because GitHub
   reports them as `Other` rather than as copyleft.
4. Pin anything whose *default behaviour* carries a licence implication.
5. Note which image a dependency lands in. The GPU worker and the CPU images have
   different dependency sets on purpose; a package added to the wrong one changes
   what is distributed.
6. Add it to the correct table above and update the review date.
7. Check it landed in the committed tree: `make licences` after CI has run, then read
   `licenses/report.json`. A package that arrives transitively will not appear in any
   requirements file — which is how both of this project's licence incidents got in.
